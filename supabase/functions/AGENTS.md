# Edge function decisions
- Utkal platform Cashfree uses service-only settings and immutable attempt/order binding, distinct from merchant and wallet payments; disabled settings block new collection but preserve capability-validated verification and signed webhooks for existing attempts. Return checks are bounded, capabilities stay fragment-only, and notifications cannot block committed confirmation.
- JD stock hot/rotating targets exclude other suppliers; JD imports deduplicate by SKU, never title, use stable paged indexes, isolate conflicting inserts and check all watch-section arrivals during backfill, because old-page work must not block new watches.
- Newest-first (Utkal) supplier stock goes through the shared jdStockQuantity/jdStockVisibility helper in import and stock sync: verified in-stock maps to the unlimited-stock marker and only verified supplier stockouts zero it, because the supplier quantity is an availability flag and website orders must never consume stock.
- City/store-directory pages (`/stores`, `/stores/:city`) read `public.store_locations` (published rows only) and build all wording through `supabase/functions/_shared/storeLocations.ts`, shared by the app and bot-render, because human and crawler output must never diverge and only merchant-verified facts may appear; delivery-only cities must never be presented as physical branches or carry Store schema.
- Utkal brand-category headings, intros, FAQs and related links come from one shared helper (_shared/utkalCategorySeo.ts) used by the app and bot-render, built only from category names and listed product titles, because crawler and shopper pages must match and must not invent facts.
